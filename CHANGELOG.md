## 2026-09-20 — The render's parent was its own derivation, and an empty page's parent was nothing (`SIGNOFF-REPAIR.11.24.1.3.1.1`)

`REASONBRAID-REPAIR-0311`. Found while scoping the snapshot leaf: there were no rendered bytes to snapshot, because the worker never captured any.

- 🔴 **The parent equalled the derivation, byte for byte, on every render.** `parent_digest` was `digest(concatenation of the chunk texts)`, and the browser worker derives exactly **one** chunk — `body.inner_text()`, whole — so the concatenation *was* that chunk's text. §12.6 is written to keep those apart: *every transformation is a `Derivation` edge*, and *a quote, summary, OCR result, model-generated caption, or repository analysis is not the original source*. An edge whose parent and child are the same bytes asserts a distinction and encodes none.
- 🔴 **The empty case was worse.** With no rendered text the chunk list is empty, the concatenation is empty, and the receipt named a parent that was **nothing at all** — for a real page that simply produced no text.
- ✅ **The parent is now the page's own bytes.** The worker reads the serialized document from the browser before the response is shaped, publishes it as `document`, and digests **it**; the rendered text stays a derivation of it. The bytes are **carried**, not merely digested: an evidence snapshot is addressable by its raw-byte digest, and a digest with no bytes behind it is a claim about an artefact nobody kept.
- ⭐ **The construction is now a pure function so that a control can guard it** — `SIGNOFF-REPAIR.7.3.6.3`'s move, applied a second time in the same file and for the same reason. Inline in the render, the parent/derivation distinction could only be exercised by driving a real Chrome, and the two lines that collapsed it would have needed a browser to catch. The new controls are offline.
- ⛔ **The output ceiling is unchanged in meaning, and that is derived rather than chosen.** 4 MiB used to bound the rendered text alone; it now bounds **document + text**, because the limit names the worker's *output* and a second artefact on the wire is more output. Bounding each separately would have doubled the worst case silently, which is inventing a number by omission.

## 2026-09-20 — A receipt is earned by an offer, and the proxy it replaces was wrong in both directions (`SIGNOFF-REPAIR.11.24.1.1.1.1`)

`REASONBRAID-REPAIR-0309`. The narrowing `migrations/0078` made possible — and the half of the old behaviour nobody had named.

- 🔴 **The cursor acknowledgement keyed on a proxy.** `.11.24.1.1.2.1` excluded rows the tail withholds *for a reason about that row* — quarantined, or past their authority — which is an ack-time guess at *was this row carried*. That leaf recorded the proxy's under-recording half: a row offered and then quarantined was skipped although the node demonstrably held it, so the receipt was suppressed and the row re-delivered.
- 🔴 **The over-recording half is the one that destroys work, and this leaf found it.** A cursor acknowledgement is a **wire input** bounded only by the server's `current_cursor`, so a node may acknowledge **past** rows this tail never offered it — one enqueued after its last poll, for instance. Those rows are neither quarantined nor authority-ended, so the proxy admitted them; and `acknowledged_at` is the retention prune's `DELETE` predicate. **Undelivered work became eligible for deletion on a number the node supplied** — `SIGNOFF-REPAIR.4.2.4`'s harm model by a second route, where there a *fenced* session could mark another session's delivery and here any session can mark a delivery that never happened.
- ✅ **`offered_at IS NOT NULL` replaces both clauses**, so the predicate answers from evidence rather than from a guess made at the wrong moment.
- ⛔ **The pre-`0078` cohort is answered, and an unscoped fallback was refused with its reason.** Those rows carry a NULL offer whatever their history, and that NULL means *not offered since the migration* — never *never offered*. Falling back to the old proxy for NULL rows would re-admit the over-recording hole for every row, because nothing in the schema tells a legacy row from one simply not yet offered. ✅ It costs nothing, and the reason is the tail's own shape: a row with no acknowledgement is still in the tail, so the node's next poll offers it, records the offer, and the next acknowledgement receipts it. Driven end to end by the control.
- ⚠️ **The two per-node reasons are honoured by construction** rather than by a clause that says so: a row carried *before* the node lost its certificate keeps its receipt, and a row never carried does not gain one. That is exactly the distinction the old clause was reaching for.
- ⚠️ **One interaction, stated rather than left to be discovered.** A row offered, then revoked, then acknowledged now earns a true receipt. Its delivery state still reads `revoked` — `migrations/0076` ranks the act above the receipt deliberately — while the retention prune ages it as a delivered row rather than by the revocation instant. Both are right for the question each answers, and a control pins the pair.
- 🔴 **A control was asserting the opposite of what it had just watched happen.** `a_revoked_grant_makes_its_undelivered_command_revoked_and_withholds_it` asserted `acknowledged_at IS NULL` with the comment *it never received this one*, one step after its own positive arm handed the row to the node — an arm that exists precisely to prove the tail could carry it. It passed under the proxy for the wrong reason. It now asserts the receipt **together with the offer that earns it**, ordered, so the pair cannot come apart.

## 2026-09-20 — The tail read is the offer, and the instant it writes does not move (`SIGNOFF-REPAIR.11.24.1.1.1`)

`REASONBRAID-REPAIR-0308`. §10.6's `offered` ships; `acknowledged` is deferred with a measured trigger.

- 🔴 **`offered` had no producer, so a row the server had handed to a transport read `queued`** — the same answer as a row it had never tried to deliver. Those are two different faults: rows stuck at `queued` say the node is not polling, and rows reaching `offered` and stopping there say it is polling and the responses are not arriving. The surface an operator reads could not tell them apart.
- ✅ **The producer is the tail read itself, because that is where the fact exists.** `replay` is the one function the handshake and the poll both read the tail through, and the rows it returns are the rows a response carries. The mark rides the **same statement** as the read, as a data-modifying CTE — two statements would be two snapshots, and the pair is not in a transaction, so a row could enter the tail between them and be delivered unmarked. ⛔ **A withheld row is not marked**: the mark is scoped to the rows the tail returns, so quarantine and an ended authority exclude a row from the offer exactly as they exclude it from the response.
