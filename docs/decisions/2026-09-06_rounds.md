# 2026-09-06_rounds.md

## Context

`PHASE-1.5.2` (backlog 17's rounds contract): the thread had no round concept —
contributions were flat, and the demo's blind round had no label. The
decomposition left the assignment rule open ("settled test-first by the
execution leaf").

## Decision

- **Rounds are SERVER-assigned; advancement is an explicit verb.** A new thread
  is round 1 (the projection's additive `current_round`,
  `#[serde(default = "default_round")]`). Every contribution lands in the
  CURRENT round and its event carries the number; `thread.advance_round` (event
  `thread.round_advanced`) is the only mover — the client never names a round,
  so round skew and forgery are impossible by construction.
- **Advancement is a new grant, deny-by-default for roles.** `thread_advance_round`
  joins the registry (the wire-name canary extended first, the `.1.1.3` lesson);
  humans carry it via the dev admin set, roles do NOT — they shape content,
  humans shape the process. A role's advance is a typed 403 with its audit row;
  a closed thread refuses it 409 (`invalid_transition`).
- **No core state-machine change.** Rounds are a projection fact + event-body
  fact, not a thread state: `open` threads advance any number of times, and the
  round rides the contribution event exactly like `.1.5.1`'s kind does — the
  event-layer growth pattern, re-applied.

## Consequences

- The two-host demo's THREAD_A now advances after the agent contribution and
  asserts both the projection round (2) and the contribution's round (1); the
  CLI e2e drives the verb through the real binary; the new `command_api` test
  covers the round-1 default, the role 403, the advance event + projection, the
  round-2 contribution, and the closed-thread refusal.
- `.1.5.2` complete; `.1.5.3` (the honest close) remains.

answers:

- **Server-assigned facts cannot be forged by the client.** The round is
  assigned at the boundary, so the rule never needs a "current or current+1?"
  validation ladder — the client CANNOT name a round, so every contribution is
  round-true by construction. A client-supplied field would have created the
  mismatch class for no gain.
- **A process-shaping act deserves its own grant name.** Advancing a round is
  not contributing content; borrowing `thread_contribute` would have blurred
  the audit trail. The registry's canary failed first when the new variant
  landed, so the wire name was never forgotten.
