ROADMAP :784 lists nine provider-attempt states; the code has seven (`crates/reasonbraid-core/src/state.rs:237-245`: no `planned`, `reserved`, `accepted_known`, `streaming`, `cancelled_known`), and `journal_lost` exists only in one doc comment (`crates/reasonbraid-server/src/node_channel.rs:45`).

## Why this order

By exposure. `.4.4.1` closes an ambiguity with no evidence in ordinary operation (a refused retry's own dead letter) and silently discards an operator's verdict; `.4.4.2` loses spend on every late result and tells nobody; `.4.4.3` comes next because the three fixtures guard exactly the boundary `.4.4.4`–`.4.4.6` change, and a census that trusts a control which cannot see what it claims measures nothing; `.4.4.4` needs a crash in a millisecond window but the loss is paid-for and permanent; `.4.4.5` turns any network blip into a dead process; `.4.4.6` needs a hung provider; `.4.4.7` is a missing feature whose absence fails safe (the node refuses). Each is built RED first except `.4.4.3`, whose controls are strengthened and then seen to refuse a mutant.

## How to apply

- Build `.4.4.1` → `.4.4.2` → `.4.4.3` → `.4.4.4` → `.4.4.5` → `.4.4.6` → `.4.4.7`; `.4.4` closes with the last, reconciled clause by clause.
- ⛔ `.4.4.1`'s directive lookup must name the ATTEMPT: the server holds this attempt's `work_result` (the payload carries `attempt_id`), not any event under the operation; and the node must apply the directive's `terminal`, not flatten it. Whether `failed_known` redelivers is decided in that leaf against `retry_decision`, which today refuses `failed_known` as terminal — `.11.4.7.2.1.5.5`'s closure claimed a redelivery the node does not perform.
